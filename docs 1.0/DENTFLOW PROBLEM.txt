1. TUJUAN TUGAS (TD-PAY-007)
   Judul: Tidak Ada Webhook untuk Payment Failure / Refund
   Deskripsi: Midtrans mengirim webhook untuk refund dan failure, tapi kita hanya handle payment success.
              Jika payment refund terjadi, invoice tetap status PAID dan tidak ada audit trail untuk refund.
   Perbaikan yang diminta: Tambahkan handler untuk webhook refund dan failure, dengan state machine yang sesuai (PAID → REFUNDED).

2. APA YANG SUDAH KITA LAKUKAN (CEK > VALIDASI > PERBAIKAN)

   A. CEK KONDISI AWAL
   ----------------------------------------------------------------
   - Webhook handler: hanya handle 'capture'/'settlement' (success) dan 'deny'/'expire'/'failure' (gagal)
   - Status REFUNDED: BELUM ADA di database constraint 'invoices_status_check'
   - Constraint saat ini: CHECK (status IN ('UNPAID', 'PARTIAL', 'PAID'))

   B. VALIDASI DATA
   ----------------------------------------------------------------
   - Query \d invoices menunjukkan constraint yang sama: 'UNPAID', 'PARTIAL', 'PAID'
   - Tidak ada data dengan status selain UNPAID dan PAID (8 UNPAID, 8 PAID)

   C. UPAYA PERBAIKAN YANG SUDAH DILAKUKAN (SEMUA GAGAL)

   Upaya 1: Migration baru (027_add_refunded_status.sql)
   - Hasil: Dibatalkan karena user minta TANPA migration baru

   Upaya 2: ALTER TABLE langsung di database
   ----------------------------------------------------------------
   ALTER TABLE invoices DROP CONSTRAINT IF EXISTS invoices_status_check;
   ALTER TABLE invoices ADD CONSTRAINT invoices_status_check
   CHECK (status IN ('UNPAID', 'PARTIAL', 'PAID', 'REFUNDED'));

   - Hasil: Query berhasil (0 error), tapi constraint tetap ('UNPAID','PARTIAL','PAID')
   - REFUNDED tidak masuk

   Upaya 3: DROP & RE-CREATE dengan syntax berbeda
   ----------------------------------------------------------------
   ALTER TABLE invoices DROP CONSTRAINT invoices_status_check;
   ALTER TABLE invoices ADD CONSTRAINT invoices_status_check
   CHECK (status::text = ANY (ARRAY['UNPAID'::text, 'PARTIAL'::text, 'PAID'::text, 'REFUNDED'::text]));

   - Hasil: Sama, constraint tetap ('UNPAID','PARTIAL','PAID')

   Upaya 4: Update constraint via pg_constraint (langsung ke system catalog)
   - Hasil: Tidak diizinkan (system catalog read-only)

3. GEJALA MASALAH (YANG TERJADI DI TESTING)

   A. Perintah ALTER TABLE berhasil dijalankan (tidak ada error)
   B. Tapi constraint tetap sama setelah verifikasi ulang
   C. \d invoices masih menampilkan: ('UNPAID','PARTIAL','PAID')
   D. REFUNDED tidak muncul di manapun dalam constraint

4. ROOT CAUSE (DUGAAN KUAT)

   Kemungkinan 1: Ada sistem caching di PostgreSQL yang tidak langsung update
   - Tapi ini tidak umum, karena \d invoices seharusnya menunjukkan state terkini

   Kemungkinan 2: Ada trigger atau event yang mencegah perubahan
   - Perlu cek: SELECT * FROM pg_trigger WHERE tgrelid = 'invoices'::regclass;

   Kemungkinan 3: Ada table inheritance atau partition yang override constraint
   - Perlu cek: SELECT * FROM pg_inherits WHERE inhparent = 'invoices'::regclass;

   Kemungkinan 4: Ada transaction yang belum di-commit (meskipun sudah AUTOCOMMIT)
   - Perlu cek: SHOW autocommit;

   Kemungkinan 5: Ada dependency dengan constraint lain (misal valid_paid_state)
   - Perlu cek dependency tree: pg_depend

   Kemungkinan 6: Ada constraint dengan nama yang sama di schema lain
   - Perlu cek: SELECT conname, connamespace::regnamespace FROM pg_constraint WHERE conname = 'invoices_status_check';
